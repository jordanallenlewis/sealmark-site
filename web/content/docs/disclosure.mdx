The policy for security findings in other people's servers is on one page: [sealmark.dev/disclosure](/disclosure/). In short: a private email to the maintainer (plus a GitHub private vulnerability report where the repository has them on), 14 days to reply with one reminder, and publication at a fix or at day 90. A security finding is never posted in a public issue.

## If you run Sealmark on someone else's server

A bypass your own run shows in a server you do not maintain is a local result. Give the maintainer the chance to fix it before you share it, in the same spirit: report it privately, wait for a reply, and publish once it is fixed or 90 days have passed. See also [Safety](/docs/safety).
