Error handlers that dump `process.env` or a config object are a classic way to leak API keys into a model's context. This check plants two fake secrets in the server's environment and looks for them in what the server says.

## Probe details

For a server the harness starts (stdio, or `--start` with `--url`), the harness adds two random canary variables to the server's environment. Their names and values are in [Environment](/docs/reference/environment#the-canary-variables). It then scans, for either value:

1. the full `tools/list` reply;
2. every response captured by [robust-input](/docs/reference/checks/robust-input), including error text and JSON-RPC error messages. They are scanned in full; only the copy shown in the evidence line is shortened.

No extra call is made for this check. It reads what the other core checks already collected. The canary values are shown as `<canary>` in the recorded server environment, so a shared report does not carry them.

## Thresholds

| Verdict | When |
|---|---|
| fail | a canary value appears in the `tools/list` reply or in any captured response |
| pass | no canary appears, and at least one response was captured to scan |
| inconclusive | no response was captured to scan (for example every tool's properties are untyped and none has required arguments, so `robust-input` made no call). On this critical check that makes the suite grade provisional |
| n/a | the harness did not start the server (an HTTP server you started yourself, with the reason "canary injection needs a server Sealmark starts (stdio, or --start with --url)"), or it declares no tools. The suite is still graded on its other checks |

## Limits

- Only the two canary variable names are covered. A server that leaks a variable it reads under a different name, or leaks only on a path the harness never triggers, passes.
- The responses scanned are mostly error responses to malformed calls, so a pass is weak evidence: the two canaries did not appear in the handful of responses the harness provoked.
- A server the harness did not start is not tested at all.
- A server that prints its environment on purpose, such as a debug tool, fails.
