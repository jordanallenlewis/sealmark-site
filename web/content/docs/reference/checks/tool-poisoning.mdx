This check reads the text a server hands to a model and looks for the phrases and hidden characters that tool-poisoning attacks use. It is a lint over declared metadata. It does not look at what a tool returns when called.

## What is scanned

No tool is called. Every string in every tool definition is scanned, to a nesting depth of 8: `name`, `title`, `description`, all text inside the `inputSchema` (parameter descriptions, enum values, defaults) and any other string the tool object carries. The `name`, `title`, `description` and `uri` of every prompt and resource the server lists are scanned with the same rules. Matching is case-insensitive. The patterns themselves are in the Probes list above.

Each evidence line says which tool and which field matched, whether the match was strong or weak, and quotes up to 80 characters of the matched text. If the server declares no tools the check is `n/a`; if the `tools/list` reply could not be parsed it is `inconclusive` (see [protocol](/docs/reference/checks/protocol)).

## Strong and weak indicators

The Probes list does not say which tier a pattern is in. Each has a separate effect:

- **Strong** gives `fail`: the instruction to ignore prior instructions, the `<IMPORTANT>` block, the three instructions to read or send a credential file, secrets or conversation data to a URL, `exfiltrat`, the instruction to read a `.env` file and pass it on, hidden or bidirectional control characters, and ESC, NUL or a C1 control. They have almost no legitimate reason to appear in tool metadata.
- **Weak** gives `part`, when no strong indicator is present: every other pattern in the list, and a description longer than 4,000 characters (hidden instructions hide in long text). Honest text can contain them, so they are flagged for a human.

Details the pattern text does not carry:

- The credential paths are `~/.ssh`, `.ssh/id_`, `id_rsa`, `id_ed25519`, `id_ecdsa`, `id_dsa`, `.aws/credentials`, `/etc/passwd`, `/etc/shadow`, `.netrc` and `.git-credentials`. A path with no read or send instruction around it is weak.
- Before the secrets-to-a-URL pattern matches, phrases that say how the tool authenticates are removed (`using`, `with` or `via`, an optional `your`, `the` or `a`, up to two words, then a secret noun), so "upload the file using your API token; see https://docs.example.test" does not match.
- Hidden characters are strong for: U+200B; U+202A to U+202E, U+2060 to U+2064 and U+2066 to U+2069; the Unicode tag block U+E0000 to U+E007F; a run of three or more of U+200B to U+200F, U+2060 and U+FEFF; and a U+FEFF that is not first. The only tag-block exception is the three exact tag sequences of the England, Scotland and Wales flag emoji, because any other tag run can carry hidden ASCII.
- One or two of U+200C to U+200F, or a U+FEFF at the very start, is weak: these are ordinary in emoji sequences and right-to-left text.
- Other C0 controls and DEL are weak, because they are usually accidents such as pasted binary text. Tab, line feed and carriage return are never flagged, so CRLF line ends are clean.

## Thresholds

| Verdict | When |
|---|---|
| fail | at least one strong indicator |
| partial | weak indicators only |
| pass | no indicator matched |
| n/a | the server declares no tools |
| inconclusive | the tool listing could not be parsed |

Why two tiers: one benign sentence, such as a safety note that mentions the system prompt or a description that mentions `.env`, must not cap a real server at D. Strong indicators have almost no honest use; weak ones cost half a point and are shown to a human.

## Limits

- A pass means none of the patterns matched. Paraphrased or non-English injections, and instructions split across fields, pass.
- The check looks for characters, not for what a model would do with the text, and nothing about behaviour at call time or injection through tool output (see the [known blind spots](/docs/methodology#known-blind-spots)).
- A description that legitimately documents reading a `.env` file or a path such as `~/.ssh/id_rsa`, or a security tool that quotes an attack phrase it detects, can still match.
